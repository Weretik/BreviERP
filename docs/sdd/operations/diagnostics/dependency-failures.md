# When a dependency fails

What breaks when one outside part stops answering, what keeps working, what the system does on its own, and what a person does. Targets for how fast each must be noticed are in [quality targets](../../architecture/overview/quality-targets.md); alerts are the Cloud Monitoring checks on `/health/ready` and the API errors.

| Dependency | What breaks | What keeps working | What the system does | What a person does |
| --- | --- | --- | --- | --- |
| PostgreSQL (managed, adm.tools) | Every API call: the admin, the site's products and its request form; `/health/ready` answers 503 | The site's cached pages and its phone number | Requests fail fast with 500/503; nothing is half-saved (one transaction per command); the uptime alert fires | Check the database in the adm.tools panel; if data is lost, restore by [backups and restore](../data/backups-and-restore.md) |
| `Host.Api` on Cloud Run (`brevierp-api`) | The same as above, the database is fine | Cached site pages | Cloud Run restarts a failing instance; the uptime alert fires | Open the service's revisions and logs ([deploy](../deployment/cloud-run-deploy.md)); roll back to the previous revision if a deploy caused it |
| Cloudflare Worker `api.brevi.com.ua` | The site and the admin cannot reach the API, though Cloud Run is healthy | Cloud Run itself; Cloud Scheduler still calls the API directly | Nothing; the uptime check on the public host fails | Check the Worker and its secret ([Cloudflare API proxy](../deployment/cloudflare-api-proxy.md)) |
| Telegram Bot API | Site requests, «Надіслати в цех» and reminders do not reach the groups | Site requests and orders are saved; the request page shows the reason | The outbox retries site requests 10 times over about 4 hours; «Надіслати в цех» shows the refusal on the order; a message that gives up is logged and posted once to the «Заявки з сайту» groups when Telegram is back ([outbox](../jobs/outbox.md)) | Check the bot token and the groups on «Нагадування» ([Telegram reminders](../jobs/telegram-reminders.md)); press «Надіслати в цех» again |
| Gmail | «Надіслати» of a КП | Creating and saving КП, the PDF | The send answers with the reason; nothing is marked sent | Check the Gmail connection ([CRM Gmail](../configuration/crm-gmail.md)); send again (the same `requestId` never sends twice) |
| Google Sheets («финансы», «Лиды Brevi») | Invoice and lead imports | Everything already imported | The task fails red on «Фонові задачі» and keeps its last error; the data stays as it was | Check the sheet's sharing and the service account; run the task again ([background tasks](../jobs/background-tasks.md)) |
| KeepinCRM, supplier sites | Client, supplier and PPE price imports | Current clients and prices | The task fails red and changes nothing | Run it again later; for prices see [PPE pricing](../data/ppe-pricing.md) |
| OpenAI | «Розпізнати» of an invoice in «Бухгалтерія» | Entering the facts by hand | The recognition answers with an error | Enter them by hand; check the key, limit and «Перевірити» on «Налаштування ШІ» |
| CDN (brevi-media.cdn.express, adm.tools) | Uploading photos; if HTTPS is down, photos on the site and in the admin | Everything else; the site shows text and prices | The upload answers with an error and saves nothing | Check the CDN account and credentials; upload again |
| Cloud Storage (accounting files) | Attaching and opening files in «Бухгалтерія» | The operations themselves | The upload answers with an error | Check the bucket and the service account's access |
| Cloud Scheduler (`brevierp-tick`, outbox dispatch, `brevierp-sync`) | Background tasks, reminders and outbox retries stop | Every request; the first try of each outbox message right after its request | Nothing; «Фонові задачі» shows no new runs | Resume or fix the job ([background tasks](../jobs/background-tasks.md), [outbox](../jobs/outbox.md)); the next run catches up |
| Cloud Run Job `brevierp-tasks` | Imports and other tasks do not run | The API and the outbox | The tick marks a run that never started or never finished as failed on «Фонові задачі» | Open the job's executions and logs; run the task again |
| Secret Manager | A new revision or job execution cannot start | The running revision keeps its secrets | The deploy fails | Check the secret and the service account's access, then sync the fork again |
| Cloud Logging / Cloud Trace | Logs or traces are missing | Everything for the users | Nothing | Nothing urgent; check the project's quotas |
