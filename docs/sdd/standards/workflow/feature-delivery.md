# Поставка функціональності та SDD

## Обов’язкова послідовність

1. Створіть папку функціональності з `specs/_templates/feature/README.md` і скопіюйте лише застосовні шаблони фаз.
2. Запишіть мету, межі, сценарії, контракти, розміщення по шарах, ризики та критерії приймання.
3. Розділяйте роботу на нумеровані фази лише коли їх можна незалежно рев’ювати або постачати.
4. Реалізуйте лише погоджену роботу в межах scope.
5. Оновіть специфікацію доказами перевірки та залишковими ризиками.

## Гранулярність документації

- Одна функціональність має одну overview specification.
- Фаза отримує власний файл, коли має окремий результат, залежність або перевірку.
- ADR потрібен лише для сталої архітектурної зміни; не створюйте ADR для звичайної use-case роботи.
- Посилайтеся на правила замість копіювання. Специфікація не має дублювати стандарти шару або безпеки.

## Definition of done

Критерії приймання позначені, релевантні тести оновлені, restore/build/test були спробувані, а результат вказує, що не вдалося перевірити і чому.
