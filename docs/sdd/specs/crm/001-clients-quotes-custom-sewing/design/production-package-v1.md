# Production package v1

Owner: Crm. Explicit export from an exact issued QuoteVersion and selected included/visible custom variants; no Workshop transport/order creation. Manager accesses owned quote; Admin all. Public UUIDs in API, typed local long keys/FKs in persistence.

Application production projection selects immutable custom configuration, exact pinned operation norms and production wage subset (minutes/minute rate/seamstress/cutting/master/bonus). Customer identity/contact, quote sale prices, supplier prices, manager/overhead totals, private notes, delivery and packaging money are excluded. Current master references are not consulted; identifiers are not replaced with invented labels.

The typed manifest (`ProductionPackageManifest`, schemaVersion1/kind brevi.production.v1) contains quote/version number, selected variant/custom version identity, norm/unit references, application placement/artwork and permitted file descriptors. JSON `manifest.json` and only production-flagged verified PDF/PNG/JPEG bytes are packaged in a deterministic ZIP (sorted UUID paths, fixed ZIP timestamps). No filenames or paths from callers. Limits: manifest1MiB, production files30, each file20MiB, total ZIP64MiB. Actual metadata/length/SHA/MIME and draft identity must match pinned file metadata; otherwise export fails without a partial artifact.

ProductionPackageArtifacts stores immutable private ZIP bytes/hash with exact QuoteVersion and canonical selected-ID hash; ProductionPackageRequests is an actor-bound request/audit journal. A replay checks current access before payload hash. Identical version/selection returns the stored artifact before live file/source reads; changed input with same requestId conflicts. An archived quote cannot create a new package; existing authorized historical download remains possible. Successful export changes neither sent state nor pricing nor quote revision. Request audit rows record generation/reuse rather than adding unsupported actions to the existing quote lifecycle enum.

Deployment: additive EmailTemplateRegistry migration first, ProductionPackages next, through CRM-only Host.Seed after verified local target/backup. Down drops history and must not be used after real use; recovery requires a verified backup or forward repair. No external provider call is inside the transaction. Private byte reads are bounded/read-only; database artifacts/audit commit atomically. API has explicit private metadata/content reads; no public storage URLs.
