# First-contact proposals and reusable selections

Source v211 has a distinct first-contact proposal behavior, not merely a free-text introduction. Evidence: `lib/introduction-proposal.ts`, `lib/introduction-saved-template.ts`, `lib/introduction-saved-template-api.ts`, `db/schema.ts` table `introduction_saved_templates`. This capability uses the same Crm quote/version/document/delivery pipeline; it is not a second quote store or mail sender.

- **R-I01:** Support three introduction layouts: general (summer + winter, four models per season/eight total), summer (four), winter (four). Each seasonal page has one configured featured model and three other distinct approved models of the correct season. Each slot selects exactly one sellable fabric Article, has fabric composition/density and a validated Brevi product URL; require an available positive large-wholesale tier. Source uses “Імпульс” trousers and “Прайм” jacket name matching for featured models. Target stores explicit versioned Catalog identity mappings in template/layout configuration, never guesses an ambiguous match or hardcodes new product IDs. Unresolved featured identity or fabric metadata is a visible blocker. Preserve source layout/slot semantics as typed configuration, with approved company presentation settings.
- **R-I02:** A Manager may create, list, rename/revise, archive and reuse **their own** saved selection templates. Admin can manage all through explicit policy. This is distinct from Admin-only issuer/document-layout administration. Template snapshots retain layout/season/slot and article/fabric selections plus email-template reference, not authoritative old prices. Reuse resolves current availability/approved backend prices and creates a new draft quote; missing references require explicit replacement. No fixed stale price or implicit send when selecting a template.
- **R-I03:** A generated introduction is a quote presentation kind with a pinned version, selected layout/version and current calculation basis, using the ordinary public-projection/PDF/outbox flow. Seasonal pages display the selected fabric metadata and the configured offered large-wholesale tier without private costs. Email text template is versioned/escaped, sender/recipient explicit. Reopening an already issued introduction retains its original prices; producing a new one from a saved selection recalculates from current inputs. Archive of reusable template does not erase issued quotes.

| Scenario | Given | When | Then |
| --- | --- | --- | --- |
| SC-I01 | Active approved season models and featured mappings | Builds general/summer/winter introduction | Required 8/4 slots, no duplicate model per season, one fabric per slot, fabric metadata/URL/positive large tier validated; missing/ambiguous mapping blocks issuance |
| SC-I02 | Manager owns a saved selection and input prices change | Revises/archives/reuses template; another manager guesses its ID | Owner operations work, foreign operations denied; new draft has current server prices, old issued document unchanged |
| SC-I03 | Valid introduction quote with verified issuer and explicit recipient | Generates seasonal PDF then sends | Correct one/two-season layout, selected public fabric/prices, no internal data; same pinned version/hash and ordinary idempotent delivery history |

Source templates are included in historical staging scope; manifest completeness and owner mapping must be verified under EN-006. Import does not enqueue an introduction send or infer product IDs from names.
