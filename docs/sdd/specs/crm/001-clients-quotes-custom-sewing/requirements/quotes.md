# Quotes, options and history

## Rules

- **R-Q01:** A quote has a stable PublicId, separate immutable human number, owner, recipient snapshot and append-only numbered versions. Saves validate the expected root revision. `draft`, `ready`, `sent` are the business states; archive is a separate flag. Ready pins a validated version; sent is recorded only after a successful authorized delivery event. Editing a ready/sent quote creates a new draft version while retaining the issued version and delivery history.
- **R-Q02:** Versions contain ordered items and ordered variants. Supported kinds: Catalog sewing Article, Catalog PPE, private custom sewing, one-off PPE and migrated legacy individual content. Catalog sewing resolves a **sellable Article**, not only a model ID. Retain client name/description/comment, catalog URL/image provenance, optional quote-only image, internal note and inclusion flags. One-off PPE requires explicit name and valid price provenance and does not create a Product.
- **R-Q03:** Three offered price tiers carry semantic tier codes, amounts, currency, quantity-range provenance, visible flags and pricing method. Preserve all three even if some are hidden. No mandatory order quantity is inferred from the source headers; optional requested quantity is a Brevi extension. Do not convert a missing/blocked tier into zero. Reject a ready visible variant with no valid visible price tier.
- **R-Q04:** Server calculates with approved Catalog/Reference inputs using decimal arithmetic and existing rounding. Client submits selections/quantities/reasons, never authoritative costs, totals, coefficients or actor. A calculation basis identifies source versions, formula/engine version, normalized inputs, original and changed norms, breakdown, three tiers and blockers. Quote overrides never modify Catalog components or published prices.
- **R-Q05:** Opening, viewing, downloading, copying the saved historical content or editing only a comment must not silently reprice it. Explicit reprice previews old/new amounts and source changes; confirmation atomically saves a new version. Invalid/inactive/missing inputs block repricing without destroying the saved valid snapshot. Saving edited calculation input requires a matching server calculation token/basis, not stale browser totals.
- **R-Q06:** PPE-only manual prices require a positive amount, tier and nonblank reason, with source/effective amounts and actor/time retained. Editing sewing tier totals directly is forbidden: edit allowed composition and recalculate. One-off PPE records an explicit manual pricing method and reason without claiming a catalog source price. Existing incomplete override history is marked, never “repaired” with an invented reason.
- **R-Q07:** Search/filter by number, recipient, date, state, owner and archive is paged/scoped. Copy creates a new root and draft, preserves selected saved content provenance, records source quote/version, and never reuses the original number or delivery state. Only explicit reprice refreshes it. Transfer changes current responsibility and grants scoped access atomically; creator, snapshots, amounts, numbers and earlier audit remain unchanged.
- **R-Q08:** History shows version, action (`created`, `edited`, `recalculated` plus explicit lifecycle events), parent version, author/time and typed changes. Display snapshots, not arbitrary executable legacy JSON. Archived quotes remain accessible to authorized users and can be restored; archive does not delete versions/files.
- **R-Q09:** An unavailable current SKU, including blocked PPE 724 or inactive 931, cannot be added/priced by bypassing Catalog blockers. Historical quotations remain readable. MOD-061 Articles 452/453 use normal backend composition including the confirmed manual operation; no quote-layer SKU exception or old spreadsheet-total override.

## Scenarios

| ID | Given | When | Then |
| --- | --- | --- | --- |
| SC-Q01 | Active client, Catalog sewing/PPE | Adds items/options, changes order and visibility, saves/reopens | Recipient, ordered alternatives, three tier visibility and server-calculated snapshots round-trip |
| SC-Q02 | Saved V1 and changed Reference cost | Opens V1, edits only text, then explicitly reprices | Reading/text edit retain price basis; reprice comparison identifies changes and creates V2 only after confirmation |
| SC-Q03 | PPE and sewing variants | Enters PPE override/reason, tries a sewing total override or forged costs | Valid PPE tier change is audited; unsupported override/forged basis fails without partial save |
| SC-Q04 | Two editors at revision N; repeated network write | Both save, one retries same requestId | One revision wins; stale request is 409; identical retry returns original result, changed payload with same key is 409 |
| SC-Q05 | Assigned quote with sent version | Transfers, copies, archives and restores within access rights | Correct owner scope, new copied root/number, retained history; no recalculation or resurrection of sent events |
| SC-Q06 | One-off PPE or legacy individual item | Saves/loads or normalizes for migration | Private typed content survives without an automatic Product; unknown legacy kind is quarantined rather than dropped |
| SC-Q07 | Missing prices, zero/negative input, hidden tiers, blocked/inactive SKU | Prepares a ready quote | Field-specific blockers prevent false zero/hidden-only offers; stored earlier version remains readable |
