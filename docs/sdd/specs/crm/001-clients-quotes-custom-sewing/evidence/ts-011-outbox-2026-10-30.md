## Delivered backend slice

Implements SC-D03 / the [P6 delivery design](../design/delivery-outbox-p6.md) as disabled-by-default backend code. The runtime prerequisite EN-004 still requires actual delegated consent/profile verification and a controlled sandbox round-trip. No live provider call, real mail, import, commit, push or frontend change was performed by this contributor.

Explicit current-owner/Admin enqueue binds actor/requestId, expected quote revision, the exact current issued quote version, intact succeeded PDF, existing immutable email template and bounded recipient/manager display name. Subject/body are rendered server-side from saved recipient/issue number and the versioned template. Provider/sender, expanded plain text, PDF bytes/SHA and original actor/time are pinned immutably. Queue is not sent and does not revise the quote. Disabled/unready configuration maps to503 without insertion. Current authorization precedes replay comparison; the exact key returns the same delivery at its current status, changed intent conflicts.

A new requestId cannot circumvent a queued/sending/reconciling/unknown attempt for the same quote/version and case-insensitive recipient. The quote row lock serializes admission. The guard returns409 `delivery_unresolved_attempt_exists`, while exact-key replay and a distinct explicit recipient remain available. After a confirmed terminal outcome a fresh explicit same-recipient command is permitted; there is no implicit retry endpoint.

Worker claims at most one delivery with committed lease and immutable attempt event before provider IO. SQL candidate selection is bounded20 and uses `FOR UPDATE ... SKIP LOCKED`; recipient readiness and pinned provider/sender identity are checked. Queued archived quotes are cancelled without HTTP, using a quote row lock to serialize archive/claim. Expired in-flight attempts and Unknown always use read-only reconciliation, never another submit. Unknown backs off5minutes. A lease token/time guard rejects stale finalizers. Successful finalization atomically writes the version-specific event/state and updates the quote to sent only if that version is still current+issued and state ready. Newer drafts remain drafts. Sent means provider acceptance rather than recipient delivery/read.
