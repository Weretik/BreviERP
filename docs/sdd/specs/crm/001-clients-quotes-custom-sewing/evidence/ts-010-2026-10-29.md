## Implemented boundaries

- Domain: `Quote.PrepareReady` protects revision/access/state and `QuoteIssue` pins the exact saved quote version, active issuer/template versions, human number and ready time. An edit after ready preserves the previously issued version.
- Application: `Quotes/PrepareQuote` validates recipient, current version/revision, included items, visible variants/positive visible tiers, UAH/tax basis and pricing blockers. It checks active settings and a selected server-managed logo before allocating a number. Number allocation, issue pin and quote mutation journal share one transaction and requestId replay. `Documents/Projection` composes only public quote fields and pinned settings; it rejects missing visible prices or an unprovisioned selected logo.
- Documents: `RenderQuotePdf` queues an artifact for an authorized issued version; `GetQuoteArtifact` distinguishes metadata from saved bytes. The artifact records pinned IDs, render key, state/attempt, generation time and SHA-256. Retries reuse the same identity. Private content is read only after quote-scope authorization; a historical download reads saved bytes instead of repricing or rerendering.
- Infrastructure: quote issue mappings and `Persistence/Documents/{Reading,QuoteArtifacts}` keep source loading, artifact lifecycle and EF storage apart. The existing renderer remains a distinct Infrastructure adapter; the hosted worker/store/source loop passed its separate isolated PostgreSQL checks. API keeps ready and PDF endpoints thin and role-scoped.
- Canonical OpenAPI: `crm/quote-drafts.openapi.yaml` includes ready; `crm/quote-pdf.openapi.yaml` defines `renderCrmQuotePdf`, `getCrmQuotePdfArtifact`, `downloadCrmQuotePdfArtifact`. The aggregate references the operations. The frontend has not synced this uncommitted contract.

## Focused functional and responsibility audit

`PrepareQuote` owns ready checks/transaction orchestration, while `Documents/Projection` owns only the allowlisted public content. `RenderQuotePdf` and `GetQuoteArtifact` are separate use cases; `Documents/QuoteArtifacts` owns private artifact state and bytes, and `Documents/Source` owns authorized pinned-row reads. The hosted worker coordinates queue claims and rendering outside HTTP, while the API controllers only map authenticated requests/results. Domain issue/artefact state, Application ports/use cases and Infrastructure EF/renderer remain in their respective layers.

The largest new TS-010 production files are `QuotePdfArtifactStore` (124 lines), `QuotePdfArtifact` (114), `QuotePublicDocumentProjectionBuilder` (82) and `QuotePdfWorker` (74). The remaining frontend/deployment work is a separate boundary, not a reason to move backend responsibilities into this slice.
