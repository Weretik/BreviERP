## Scope and design

- EN-005 is confirmed in D-12. Admin creates an immutable issuer/template version pair and explicitly activates it with expected revision and requestId replay; Manager may read the active pair. No production defaults or active row are silently seeded.
- Domain separates issuer values, document template text, and active pointer. Application separates GET, create, activate, persistence and numbering ports. Infrastructure owns transaction/replay storage, EF mappings and number allocation; API owns strict request mapping. The logo is a controlled logical key (`brevi-wordmark`) or null, not a URL fetch.
- `AddIssuerSettingsAndNumberSequence` adds five Crm tables: `IssuerSettingsVersions`, `DocumentTemplateVersions`, `DocumentSettingsState`, `DocumentSettingsMutations`, `DocumentNumberSequences`. Typed long domain IDs and Guid public version IDs are separate. A PostgreSQL trigger rejects UPDATE/DELETE of immutable version rows. The Down path removes only these newly added tables and trigger/function; it would delete real settings if used after deployment.
- Number allocation requires the caller's ready transaction. A period advisory lock serializes concurrent allocation, scans known quote numbers in either `N-M-YYYY` or `N/M/YYYY`, advances the monthly counter, and emits `N/M/YYYY` starting at 10. Unknown future historical imports remain a P7 reconciliation concern.
- Canonical `crm/issuer-settings.openapi.yaml` defines `getCrmIssuerSettings`, `createCrmIssuerSettingsVersion`, and `activateCrmIssuerSettings`; aggregate `openapi.yaml` references them. POST returns 200 under the existing Result mapping, matching runtime behavior.
