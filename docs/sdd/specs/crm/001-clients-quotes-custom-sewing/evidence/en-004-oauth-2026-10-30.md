User chose Gmail, a sender and a separate sandbox recipient. At this checkpoint the user has no OAuth client yet and requested setup instructions. Implemented secure configuration consumption and an offline-tested token source, plus a user-run consent helper. No actual credentials were read/copied/imported, no Google OAuth consent occurred, no mail was sent, and no database/remote state was changed by this package. Coordinator owns DI/shared status/feature-map integration.

Files under Infrastructure `Delivery/Gmail/OAuth/`: `GmailOAuthOptions.cs` (secure-host option keys and bounded structural prerequisites), `GmailOAuthResponse.cs` (16KiB bounded JSON and grant parsing), `GmailOAuthAccessTokenSource.cs` (one-attempt refresh, profile proof, cancellation and serialized expiring cache). Existing Application token port is unchanged. Configuration uses `Crm:Delivery:Gmail:OAuth:{ClientId,ClientSecret,RefreshToken,TimeoutSeconds}`. Options must not be logged/serialized. Root wiring must register one singleton source and a no-redirect/no-retry named client.

The source checks sender identity with the same access token before returning it. Explicit refresh scopes must include send+readonly; omitted scope preserves Google's original grant and is not represented as proof of both scopes. Tokens are cached from request start until expiry minus60seconds; no durable token copy and no mutable runtime account switch. Failure returns null, caller cancellation propagates; token/profile requests share one bounded timeout. Profile matching currently requires the primary mailbox; sending as a distinct alias is not introduced.

## Consent helper

`tools/gmail-oauth-setup.py` is explicit user-run setup using downloaded Desktop client JSON. It opens a system browser, binds loopback only, uses PKCE/S256 + randomstate, does not log callback queries, and validates received grant/profile before piping JSON over stdin to existing Host.Api user-secrets. Token/profile endpoints fixed; redirects disabled; response/time bounds enforced. Header/body callback guards and socket timeouts reject malformed/slow requests. It always saves Enabledfalse/Sandboxtrue and never sends mail. No live addresses or secrets are embedded in code/tests/docs. [User instructions](../../../../operations/crm-gmail-oauth.md).
