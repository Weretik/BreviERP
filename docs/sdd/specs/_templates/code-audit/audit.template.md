- **Feature:** `docs/sdd/specs/<module>/<NNN>-<feature>/`
- **Scope:** `<точні use cases, модулі та шляхи>`

Аудит охоплює наявний код, який feature використовує або змінює, та новий код у погоджених межах. Сторонні модулі оглядайте лише настільки, наскільки це потрібно для перевірки залежностей і контрактів; їхній рефакторинг не входить до цього аудиту.

## Перед реалізацією: фактична база

- [ ] Знайдено точні файли в `src/Modules/<Module>/`, за потреби `src/BuildingBlocks/`, `src/Bootstrapper/` і `tests/`; оглянуто їхні виклики, публічні контракти та поточне використання.
- [ ] Визначено, де належать інваріанти (`Domain`), оркестрація use case, validators і DTO (`Application`), persistence та інтеграції (`Infrastructure`), HTTP binding і mapping (`Api`), реєстрація та запуск (`Host`).
- [ ] Звірено заплановані зміни з `docs/sdd/architecture/overview/layers.md`, `docs/sdd/standards/backend-rules.md` і наявним design feature. Точні шляхи та потрібні межі записано в design або task-файлі feature; цей аудит посилається на них, а не дублює весь design.

## Після реалізації: перевірка всього scope

- [ ] Переглянуто весь код feature в погодженому scope, включно з повторно використаними й новими файлами, а не лише останній `git diff`.
- [ ] Перевірено напрям залежностей між шарами й модулями, відсутність циклів, бізнес-правил в `Api`/`Infrastructure` та transport/persistence залежностей у `Domain`.
- [ ] Для кожного use case перевірено розміщення command/query, handler, validator, DTO та specification. Specification належить своєму use case; спільний код винесено лише за наявності реального повторного використання.
- [ ] Перевірено відповідальності EF mappings, repositories/read models, інтеграцій, міграцій, HTTP controllers/mappers та реєстрації в host тільки там, де вони входять до scope.
- [ ] Для кожного поділу, перенесення або рішення залишити код разом записано конкретну причину. Назви файлів і top-level types, межі public API та сумісність контракту перевірено після зміни.
- [ ] Після структурних змін виконано релевантні unit, integration, API та architecture тести; команди й результати записано нижче. Для поведінкових змін збережено зв'язок з acceptance-сценаріями feature.
