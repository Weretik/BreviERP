# Фаза 01: Доменна модель та інваріанти

**Статус:** чернетка  
**Залежить від:** прийнятого батьківського SDD  
**Блокує:** роботу над infrastructure та application

## Результат

Доменна модель може представити бізнес-можливість без недопустимого стану.

## Проєктування

- Корінь агрегату/сутність:
- Value objects і типізовані ID:
- Обов’язкові поля та nullability:
- Інваріанти й переходи стану:
- Доменні помилки:
- Доменні події, якщо потрібно опублікувати завершений бізнес-факт:

## План файлів

```text
<Module>.Domain/
├── Entities/<Area>/
├── ValueObjects/
├── Errors/
└── Events/
```

## Критерії приймання

- [ ] Недопустимі значення не можуть створити або змінити агрегат.
- [ ] ID/value objects забезпечують власну концептуальну валідацію.
- [ ] Не додано залежність від EF, HTTP, DTO, контролера чи infrastructure.
- [ ] Доменні події накопичуються лише за потреби.
