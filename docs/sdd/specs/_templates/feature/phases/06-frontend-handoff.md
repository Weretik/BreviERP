# Фаза 06: Передача frontend-контракту

**Статус:** чернетка  
**Залежить від:** фаз 04 і 05  
**Блокує:** завершення функціональності для API, який споживає frontend

## Результат

Frontend отримує стабільний самодостатній документ контракту й не потребує переглядати backend-handler-и.

## Обов’язковий документ контракту

Заповніть `contracts/api-contract.md`:

- назва endpoint-а, HTTP-метод і фінальний URL;
- вимога автентифікації/авторизації;
- поля route, query і body DTO, типи, обов’язковість і значення за замовчуванням;
- поля response DTO, типи, nullability і приклад;
- пагінація, сортування, фільтрація та семантика enum;
- статуси успіху й помилок;
- семантика ідемпотентності/повторів для write-операцій;
- повідомлення про сумісність/deprecation.

## Критерії приймання

- [ ] Контракт не посилається на внутрішню сутність, DbContext або тип handler-а.
- [ ] Frontend-розробник може викликати API лише за документом контракту.
- [ ] Поля контракту збігаються з OpenAPI/runtime-відповіддю, перевіреною у фазі 05.
