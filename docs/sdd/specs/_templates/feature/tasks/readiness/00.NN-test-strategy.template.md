- [ ] Вибрати найвужчий корисний рівень тестування для кожного сценарію й технічного ризику.
- [ ] Визначити наявні fixtures, builders, containers або test hosts для повторного використання.
- [ ] Визначити сфокусовані Red-команди й команди зачепленого regression-набору.
- [ ] Не повторювати повний сценарій на кожному рівні без окремого ризику.
- [ ] Зафіксувати дозволені test-first винятки й замінні перевірки.
- [ ] Оновити `traceability.md` запланованими назвами тестів або evidence targets.

## Виняток і verification

Ця задача планує тести, а не змінює поведінку, тому Red-first automation не має сенсу. Перевірте, що кожен сценарій має виконуваний доказ або явну обґрунтовану ручну перевірку.

## Checkpoint

AI може почати кожну тестовану задачу `TS-*` із конкретного сфокусованого тесту й команди.
