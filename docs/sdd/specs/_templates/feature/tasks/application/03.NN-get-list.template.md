# Шаблон підфази 03.NN — Application: отримання списку

- [ ] T021 Створити `<Get…ListQuery>` і DTO елементу списку у `<точний шлях>`.
- [ ] T022 Визначити та реалізувати дозволені фільтри, сортування, пагінацію й метадані відповіді списку через `PagedResult<IReadOnlyList<TItem>>` і `PagedInfo`.
- [ ] T023 Додати `AsNoTracking` read projection `Specification<TEntity, TItem>` із SQL `Select` через погоджену read abstraction; не materialize-ити aggregate для ручного mapping у handler.
- [ ] T024 Реалізувати handler, який повертає `PagedResult<IReadOnlyList<TItem>>`; порожній список є успішним результатом.
- [ ] T025 Додати query validator лише за потреби: допустимі фільтри, sort field, page/page size та формат identifier.
- [ ] T026 Явно повернути погоджений `Ardalis.Result`: success із порожнім або заповненим списком, invalid parameters та error.
- [ ] T027 [P] Додати handler і, за наявності, validator-тести: заповнений список, порожній список, invalid parameters та error case.
- [ ] T028 Перевірити передачу `CancellationToken` і участь query у Mediator pipeline.

## Checkpoint

Запит списку не завантажує зайві дані, коректно обробляє порожній результат, має потрібну валідацію, явні результати та тести.
