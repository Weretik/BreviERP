# Шаблон підфази 03.NN — Application: контракти та доступ до даних

- [ ] T016 Перевірити наявні Application contracts, DTO та mapping helpers у модулі; повторно використати їх, якщо вони відповідають use case.
- [ ] T017 Створити або оновити лише потрібні Application contracts: команди, запити та інтерфейси сервісів/репозиторіїв у `<точні шляхи>`.
- [ ] T018 Створити окремі request/response DTO для кожної CQRS-операції лише якщо наявний Application contract не покриває потрібну форму даних; не змішувати їх із HTTP DTO та Domain entities.
- [ ] T019 Визначити мапінг між DTO, Domain model і read projection; створити feature mapper/helper лише для повторюваного або нетривіального мапінгу, інакше залишити мапінг локальним та явним у handler.
- [ ] T020 Додати потрібні Application abstractions для даних: write repository/unit of work для команд і read repository/query service для читання.
- [ ] T021 Не додавати пряму залежність Application від DbContext, якщо це не погоджено архітектурою.

## Checkpoint

Кожен use case має власні контракти та використовує погоджений шлях до даних.
