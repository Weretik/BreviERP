# Виконання і фіксація результату

## Виконання checkbox-задач

1. Виконуйте задачі у порядку файла фази, крім явно позначених `[P]` незалежних
   задач після виконання їхніх залежностей.
2. Перед зміною прочитайте поточний вміст файла; збережіть наявне кодування,
   стиль і не пов'язані зміни користувача.
3. Вносьте найменшу зміну, яка повністю закриває задачу. Дотримуйтеся напряму
   залежностей `API -> Application -> Domain`; Infrastructure залежить тільки
   від внутрішніх шарів.
4. Для use case застосовуйте CQRS через Mediator. Domain володіє інваріантами,
   Application — orchestration і FluentValidation, API — лише HTTP-мапінг,
   Infrastructure — persistence та зовнішні адаптери.
5. Після локальної перевірки замініть лише позначку задачі `- [ ]` на `- [x]`.
   Не позначайте частково зроблену, заблоковану або неперевірену задачу.

## Де фіксувати результат

| Подія | Де фіксувати |
| --- | --- |
| Закрито task ID | У поточному `tasks/<NN>-*.md`: `- [ ]` → `- [x]`. |
| Уточнено scope або вимогу | У `README.md` або відповідному файлі `requirements/`. |
| Обрано domain, persistence чи integration-рішення | У `design/domain.md`, `design/infrastructure.md` або `data-model.md`. |
| Уточнено HTTP/integration contract | У `contracts/api-contract.md` і, після погодження, у `docs/sdd/contracts/<module>/<feature>.openapi.yaml`. |
| Виконано перевірку або знайдено blocker | У поточній фазі чи delivery report, якщо це передбачено task. |

Не ставте позначки в майбутніх фазах і не заповнюйте delivery checklist до
фази `05`, якщо поточна задача прямо цього не вимагає.
