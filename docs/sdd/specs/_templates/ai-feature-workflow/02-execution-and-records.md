# Виконання й фіксація результатів

## Виконання тестованої технічної задачі

1. Перевірте `TS-*`, `Covers`, залежності, точні шляхи, рівень тестування та checkpoint задачі.
2. **Red**: додайте найменший сфокусований тест для вибраного правила або сценарію. Запустіть його й переконайтеся, що він падає через відсутню або неправильну поведінку.
3. **Green**: реалізуйте найменшу завершену зміну, яка робить тест успішним. Зберігайте напрямок залежностей `API → Application → Domain`; Infrastructure реалізує інтерфейси, якими володіють внутрішні шари.
4. **Refactor**: поліпшіть структуру в межах погодженого design і повторно запустіть сфокусовані тести.
5. **Regression**: запустіть зачеплений набір тестів і зафіксуйте результат.
6. Позначайте checklist steps завершеними лише після появи доказів. Оновіть рядок сценарію в `traceability.md`, потім виберіть наступну готову задачу в scope.

Не приймайте compilation failure, зламану fixture, відсутню dependency або сторонній test failure як коректний доказ Red.

## Виконання enabler або винятку

Для задачі `EN-*` зафіксуйте, чому Red-first поведінка не має сенсу, які сценарії вона уможливлює, прийняту команду або generator і замінну перевірку. Перегляньте згенерований результат; змінюйте його вручну лише коли generator не може виразити погоджений результат, і зафіксуйте цю причину.

## Де фіксувати результати

| Подія | Де зафіксувати |
| --- | --- |
| Докази Red/Green/refactor/regression | Поточний файл `TS-*` |
| Виняток enabler і замінна перевірка | Поточний файл `EN-*` |
| Завершена технічна задача | Поточний task-файл і `traceability.md` |
| Завершений acceptance-сценарій | `traceability.md` |
| Уточнена поведінка | `README.md` або відповідний файл `requirements/` |
| Технічне рішення | Відповідний design- або data-model-документ |
| Зміна контракту | Контракт feature і версійований OpenAPI |
| Blocker або відхилення | Поточна задача та рядок зачепленого сценарію |

## Дотримання scope

Вносьте найменшу зміну, яка повністю завершує поточну задачу. Не виконуйте побічних refactoring або upgrades. Після завершення переходьте до наступної готової задачі лише поки вона залишається в дозволеному користувачем scope.
