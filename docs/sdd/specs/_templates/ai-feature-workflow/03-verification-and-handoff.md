# Перевірка і передача фази

## Перевірте результат

1. Запустіть перевірки, прямо задані у фазі, застосовних `AGENTS.md` і
   `docs/sdd/standards/testing-rules.md`, якщо вони релевантні зміненим файлам.
2. Спочатку виконайте найвужчу перевірку: цільові unit, integration або API
   tests. Для фази `05` обов'язково виконайте:

   ```powershell
   dotnet restore BreviERP.sln
   dotnet build BreviERP.sln --no-restore
   dotnet test BreviERP.sln --no-build
   ```

3. Якщо команда не запускається або падає, зафіксуйте точну команду, failure
   point і чи проблема з'явилася від поточної зміни або була раніше.
4. Перегляньте `git diff` для власних змін. Вони мають відповідати поточній
   фазі; не змінюйте та не відкидайте сторонні зміни робочої директорії.

## Умова завершення

Фаза завершена лише коли всі її checkbox-задачі закриті, checkpoint виконано,
blockers відсутні або мають явне рішення користувача, а код, contracts і
documentation не суперечать один одному. Для фази `05` також має бути
пройдено `checklist/delivery-readiness.md` і підготовлено delivery report.

## Формат підсумкового звіту

1. **Виконано** — task IDs і короткий результат.
2. **Змінені файли** — лише зміни поточної фази.
3. **Перевірки** — команди, результати й ручні сценарії.
4. **Не перевірено / блокери** — точна причина; якщо їх немає, вкажіть це.
5. **Ризики / ручна перевірка** — лише реальні залишкові пункти.
6. **Статус** — `Фаза <номер> завершена. Очікую команду «Переходь до фази <наступний номер>».`

Після звіту не починайте наступну фазу й не виконуйте нових змін, доки
користувач явно не назве її номер.
