# Регламент поетапної реалізації backend-feature

Виконуйте лише точний файл фази або підфази, який передав користувач. Головні
фази `00–05` є orchestration: вони створюють потрібні окремі підфази, але не
містять усі деталі реалізації.

1. Знайдіть і прочитайте точний файл у `<feature>/tasks/` та всі застосовні
   `AGENTS.md`.
2. Прочитайте `tasks/README.md`, `README.md` feature і документи, на які
   посилається поточний файл.
3. Виконайте лише незакриті checkbox-задачі поточного файла; не починайте інший
   головний етап або підфазу без явної команди користувача.
4. Після виконання кожної задачі позначте її `[x]` у цьому самому файлі.
5. Запустіть релевантні перевірки, зафіксуйте результат у документації та
   надайте звіт.
6. Зупиніться й чекайте явної команди на наступний точний файл.

## Структура фаз

| Головна фаза | Роль | Де створюються конкретні підфази |
| --- | --- | --- |
| `00` — Readiness | вибір scope, use cases і tooling | `tasks/readiness/00.N-*.md` |
| `01` — Domain | планування Domain slices | `tasks/domain/01.N-*.md` |
| `02` — Infrastructure | планування Infrastructure slices | `tasks/infrastructure/02.N-*.md` |
| `03` — Application | планування contracts і use cases | `tasks/application/03.N-*.md` |
| `04` — API | планування HTTP/API робіт | `tasks/api/04.N-*.md` |
| `05` — Verification | планування delivery checks | `tasks/verification/05.N-*.md` |

Головний файл фази створює потрібні підфази з шаблонів і завершується. Потім
AI виконує кожен створений файл `NN.N-*.md` окремою командою користувача.
