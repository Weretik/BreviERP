# Контекст і межі роботи

## Визначте поточний файл фази

- Виконуйте **лише** точний файл, який передав користувач: головну фазу
  `tasks/00-*.md`–`tasks/05-*.md` або підфазу на кшталт
  `tasks/application/03.2-create.md`.
- Якщо користувач передав лише номер, знайдіть один відповідний фактичний файл.
  Якщо їх декілька (наприклад, `03.1` і `03.2`), попросіть точний шлях або назву.
- Головний файл `00`–`05` лише обирає та створює підфази. Після його завершення
  не починайте жодну з нових підфаз, доки користувач явно не назве її файл.
- Наступні фази можна читати лише для розуміння залежностей. Не змінюйте їхні
  задачі, код або перевірки без явної команди користувача.

## Що прочитати до змін

1. Знайдіть `AGENTS.md` від кореня репозиторію до кожного файлу, який плануєте
   змінити, і виконайте всі застосовні інструкції.
2. Прочитайте повністю `<feature>/README.md`, `tasks/README.md`, поточний файл
   фази й
   застосовні файли з `requirements/`, `design/`, `data-model.md`, `contracts/`
   та `checklist/`.
3. Для головної фази `00` і підфаз `00.N` обов'язково прочитайте весь пакет feature, зокрема
   `checklist/spec-readiness.md`; для HTTP або integration consumer —
   `contracts/api-contract.md` та відповідний файл у
   `docs/sdd/contracts/<module>/`.
4. Перевірте залежності: попередній головний етап і всі його створені потрібні
   підфази мають бути `[x]`, а checkpoint не повинен містити незакритого blocker.
5. Прочитайте лише релевантні постійні правила:
   `docs/sdd/architecture/README.md`, `docs/sdd/standards/README.md` і
   потрібні rules для domain, database, API, security або testing.
6. Перегляньте наявний код, тести й конфігурацію рівно настільки, наскільки це
   потрібно для поточної фази.

## Коли зупинитися

Не вигадуйте business rule, endpoint, DTO-поле, роль, схему даних, шлях файлу
або вимогу, яких немає у специфікації чи чинному коді. За відсутності рішення
зафіксуйте `[NEEDS CLARIFICATION: <питання>]` у профільному документі feature,
залиште задачу незакритою, коротко поясніть blocker і чекайте рішення.

Не робіть попутного рефакторингу, оновлення залежностей або змін поза scope
поточної фази.
