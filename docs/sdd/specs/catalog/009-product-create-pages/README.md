# CAT-009 — Product creation from the Admin pages

**Status:** backend implemented 2026-11-03; Admin pages in brevi-web. **Date:** 2026-11-03. **Module:** Catalog, schema `catalog`, no new module, no migration.

Follows [CAT-006](../006-products-page/README.md), [CAT-007](../007-sewing-product-card/README.md) and [CAT-008](../008-ppe-product-card/README.md). Reuses the PPE offer versions and calculator of [CAT-003](../003-sheet-pricing-parity/README.md); no formula changes.

## Goal

The Admin pages «Новий ЗІЗ» and «Нова модель» add a product the way the Google Sheet add-product instruction does: one row in «ЗІЗ» or «Моделі» with its code, name, section and working fields, and for PPE the supplier block and the first price. The manager does not pick the ID, the slug or the Russian name.

## Scope

- In: create a Sewing or PPE product with the «Товари» page fields (CAT-006) and, for PPE, the supplier fields (CAT-008); check a code before saving; preview the three PPE prices before saving.
- Out: site texts, SEO, photos and categories (planned [Content module](../../content/001-site-content/README.md)); Sewing articles and composition (added later on the CAT-007 card).
- The legacy `POST /api/v1/products` stays for now. The new Admin pages do not use it; it is removed together with the Content module.

## API

Contracts: [product-overview.openapi.yaml](../../../contracts/catalog/product-overview.openapi.yaml), [ppe-pricing.openapi.yaml](../../../contracts/catalog/ppe-pricing.openapi.yaml).

## Rules

- **R-01:** The server picks the ID: the largest product ID + 1 (1 for an empty table). Product IDs are not generated by the database.
- **R-02:** The slug comes from the Ukrainian name through `IProductSlugGenerator`, reduced to lower-case latin letters and digits joined by hyphens. When it is taken, the code is added, then a number.
- **R-03:** The name is Ukrainian only; `RuName` is a copy until the Content module owns texts. A name already used in either name column returns 409.
- **R-04:** An empty sewing code takes the next MOD-XXX: the largest `MOD-<number>` + 1, padded to three digits. A PPE product needs its site article. A code already used by a product of the type returns 409.
- **R-05:** The section must exist in Reference «Типи і розділи» and belong to the type. The season is for sewing only.
- **R-06:** A PPE product needs the supplier block: an existing Reference supplier, an http(s) supplier link, a positive price with at most 2 decimals, an existing PPE rule and a unit. A sewing product has no supplier block.
- **R-07:** After the PPE product is saved, its first approved offer version is appended (source «Створення ЗІЗ», today in Kyiv, expected version none, server actor). When the append fails, the product stays and `priceSaved` is false; the card then asks to save the price again.
- **R-08:** The code check returns whether the code is free and, when taken, the product ID and name; for sewing it also suggests the next MOD-XXX. Without a code it only suggests.
- **R-09:** The preview uses the same calculator as the saved card; nothing is saved. An unknown rule is invalid; a draft rule gives the `MissingRule` blocker.

## Design

- Application: `Features/Product/Overview/Create/` (`CreateCatalogProductCommand`, handler, validator, `ProductByNameOrSlugSpec`, `LastProductIdSpec`), `Overview/CodeCheck/` (`GetProductCodeCheckQuery`, `ProductCodeCheck`), `Overview/Shared/SewingModelCodes.cs` with `ProductByCodeSpec` and `SewingModelCodesSpec`, `Features/Pricing/Ppe/Preview/` (`PreviewPpePricesQuery`).
- API: `ProductOverviewController` (create, code check), `PpePricingRulesController` (preview), `Contracts/Products/Overview/CreateCatalogProductRequest.cs`.

## Acceptance

- **AC-01:** A sewing model without a code gets the next MOD-XXX, the next ID, a free slug and the requested active state (R-01, R-02, R-04).
- **AC-02:** A PPE product is saved with its supplier fields and a first offer version with source «Створення ЗІЗ» (R-06, R-07).
- **AC-03:** A taken code or name returns 409; a wrong or unknown section, unknown supplier or unknown rule returns 400 and nothing is saved (R-03 – R-06).
- **AC-04:** A failed price append returns 201 with `priceSaved: false` (R-07).
- **AC-05:** The code check and the preview answer before saving (R-08, R-09).
