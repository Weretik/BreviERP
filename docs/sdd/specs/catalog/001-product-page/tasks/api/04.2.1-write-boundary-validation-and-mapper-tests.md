# Підфаза 04.2.1 — Валідація write boundary та mapper tests

> Коригувальна підфаза після `04.2-http-contracts-and-behavior.md` і до
> `04.3-openapi-documentation.md`. Вона не змінює бізнес-інваріанти Application:
> API лише строго розбирає публічні string enums і повертає їхні помилки в
> погодженому HTTP-форматі.

## Мета

Усунути два різні формати `400 Bad Request` на API boundary та не дозволяти
числові або неканонічні значення enum у write JSON. Закріпити поведінку unit
тестами mapper-ів до API/integration tests підфази 04.4.

## Рішення

- Для `POST` і `PUT` неправильний `type` та неправильний
  `retailPercent.source` / `wholesalePercent.source` повертаються через той
  самий наявний формат `Ardalis.Result` validation errors, що й `ResultStatus.Invalid`.
  Рядок у тілі відповіді та новий `ProblemDetails`-envelope не створюються.
- Публічні enum-значення є case-sensitive string literals:
  - `type`: лише `Sewing` або `Ppe`;
  - `source`: лише `Reference` або `Custom`.
  Числа (`1`, `2`, `"1"`, `"2"`), інший регістр і невідомі значення не
  мапляться в Domain enum.
- Application validation залишається остаточним захистом бізнес-правил:
  API не відкидає неповний Sewing/PPE block або block іншого типу мовчки.

## Критерії приймання

- API не повертає raw JSON string для mapper validation failure.
- `"Sewing"`, `"Ppe"`, `"Reference"` і `"Custom"` є єдиними допустимими
  wire values; усі інші варіанти повертають `400` без виклику Mediator.
- Mapper tests не потребують БД, HTTP host або зовнішніх сервісів.
- Наявні бізнес-помилки Application продовжують мапитися без зміни їхнього
  error envelope.

## Checkpoint

Write boundary повертає один передбачуваний `400` contract, strict string enums
не проходять як numeric .NET enums, а мапінг Sewing/PPE захищено unit tests.
