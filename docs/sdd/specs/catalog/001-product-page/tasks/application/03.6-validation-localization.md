# Підфаза 03.6 — Локалізована validation Product use cases

## Мета

Кожна команда/запит Product повертає локалізовані помилки валідації у стандартному форматі `Ardalis.Result`: стабільний `identifier` (шлях до властивості) і повідомлення. Валідація виконується до обробника через конвеєр Mediator; обробник залишає лише перевірки БД і стану.

- [x] T050 Централізувати українські та російські validation messages/resources для Product.
- [x] T051 Налаштувати локалізацію запитів Host: типова `uk-UA`, підтримка `uk-UA`/`ru-RU`, `Accept-Language`; зареєструвати валідатори Catalog у DI.
- [x] T052 Повністю валідовувати Create/Update: common fields, collections, photos, information, characteristics, Sewing, PPE та percent source; child validators повинні повертати indexed property paths.
- [x] T053 Додати validators для Delete, GetAdminDetail і GetAdminList: ID, paging, search, categoryId, sorting.
- [x] T054 Прибрати з Product handlers validation без DB-залежності; лишити `Conflict`, `NotFound`, Reference/Media availability і state checks.
- [x] T055 Додати tests для кожного use case: український message, `identifier`/collection index, valid і boundary requests.
- [x] T056 Запустити UnitTests та Host/API verification і зафіксувати evidence.

## Критерії приймання

- Некоректний запит не доходить до обробника.
- `400` повертає стандартні Ardalis validation errors зі стабільними property path та українським message.
- Створення й оновлення мають еквівалентну модель валідації спільного тіла запиту.
- Локаль змінює тільки message, але не `identifier`.

## Докази

- `dotnet test tests/UnitTests/UnitTests.csproj --filter FullyQualifiedName~ProductValidationTests` — пройшли 11/11 тестів.
- `dotnet build src/Bootstrapper/Host.Api/Host.Api.csproj --no-restore` — успішно; чинна реєстрація Host знаходить валідатори Catalog, а локалізацію запитів налаштовано для `uk-UA`/`ru-RU`.
