# Підфаза 03.10 — Narrow Reference pricing reader для admin Product list

**Залежить від:** `03.9-admin-list-query-performance.md` і профілювання непорожньої representative page
**Design:** [admin-list-pricing-reference-reader.md](../../design/admin-list-pricing-reference-reader.md)
**Наступна verification:** `../verification/05.3-admin-list-query-performance-verification.md`

- [x] T091 Додати Catalog Application contract `IProductListPricingReferenceReader` і list-only input/result types. Контракт приймає лише distinct primitive IDs та повертає лише числові pricing fields; він не переносить Reference entities/DTO до Catalog.
- [x] T092 Реалізувати спеціалізований Reference Application query та Host adapter: set-based projections для fabrics, accessories, operations і потрібних AdditionalReferences без supplier/garment-part UI lookups; не викликати існуючі `GetAll...` UI queries.
- [x] T093 Переробити `GetAdminProductsQueryHandler`: після отримання page зібрати ID sets, викликати narrow reader один раз і застосувати наявні pricing formulas. Порожні ID sets не мають породжувати database query; list response не змінюється.
- [x] T094 Дослідити наявний mechanism invalidation Reference writes. Додати cache тільки якщо він забезпечує документований TTL, invalidation і multi-instance semantics; інакше зафіксувати свідоме рішення без cache.
- [x] T095 Додати Unit/Integration tests: pricing parity, відсутність supplier/garment-part lookup, bounded SQL command count і no-N+1 для page size 1/20/50.

## Checkpoint

Admin list отримує тільки потрібні pricing inputs batch-запитами. Повний Reference snapshot
не викликається list handler-ом; кеш, якщо з’явиться, не має неявного або некерованого
staleness.

## Результати реалізації

- List handler більше не викликає повний `IProductReferenceReader.GetSnapshotAsync()`.
  Він збирає distinct IDs з rows поточної page і викликає один
  `IProductListPricingReferenceReader`.
- Reference `GetPricingReferencesByIdsQuery` має чотири set-based numeric projections:
  fabrics, accessories, operations і AdditionalReferences. Supplier і GarmentPart UI
  lookups не входять до dependency graph query.
- Для порожніх наборів кожен Reference repository не викликається. Sewing pricing keys
  передаються тільки коли page містить Sewing Product з тканиною; PPE передає лише
  reference-backed percent IDs.
- Cache не додано: у codebase не знайдено invalidation або multi-instance semantics для
  Reference writes, тому TTL cache міг би повертати застарілі ціни.
- `ProductAdminListReadModelTests` перевіряє збереження розрахунку minimum wholesale price та один
  list-only reader виклик для page rows. `PricingReferenceQueryHandlerTests` перевіряє лише чотири
  pricing repositories без supplier/garment-part lookup.
- `PricingReferenceQueryIntegrationTests` виконується на PostgreSQL: повертає лише requested
  AdditionalReference і фіксує рівно 4 `SELECT` для ID-set розміром 1, 20 та 50 — кількість SQL
  команд не залежить від кількості товарів у page і не має N+1.
- `dotnet test tests/UnitTests/UnitTests.csproj --no-build` — 47 passed;
  `dotnet test tests/IntegrationTests/IntegrationTests.csproj` — 22 passed.
- `dotnet build src/Bootstrapper/Host.Api/Host.Api.csproj --no-restore -o %TEMP%\\brevierp-03-10-host-build` — успішно, 0 errors. Ізольований output використано, бо запущений локальний Host API блокує звичайний `bin/Debug`.
- Вимірювання end-to-end latency та порівняння до/після свідомо винесено до
  `05.3-admin-list-query-performance-verification.md`; вони не є частиною цієї реалізаційної підфази.
