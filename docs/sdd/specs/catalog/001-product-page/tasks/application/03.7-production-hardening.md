# Підфаза 03.7 — Production hardening Application

## Мета

Закрити production-ризики, виявлені під час аудиту Application-реалізації
Product. Підфаза не змінює HTTP-контракти: API-наслідки виконуються лише у фазі 04.

- [x] T057 До `CreateProductCommandHandler` і `ReplaceProductCommandHandler` додати перевірку, що всі передані `CategoryIds` існують **до** зміни aggregate-а або write operation; відсутня категорія повертає погоджений `Result.Conflict` без `DbUpdateException`.
- [x] T058 Узгодити та реалізувати collision-free, testable стратегію локального `ProductPhotoId` замість `Random.Shared`; додати тести для кількох фото одного Product.
- [x] T059 Перетворити race condition унікальних `Id`/української назви/російської назви/slug на `Result.Conflict`: DB unique-constraint violation під час create/update не має вийти назовні як 500. Додати integration-тести конкурентного або еквівалентного constraint сценарію.
- [x] T060 Переробити `GetAdminProductDetailQuery` на `AsNoTracking` SQL projection, що materialize-ить лише дані admin detail; не завантажувати повний Product aggregate для ручного mapping у handler. Зберегти повний погоджений detail contract і додати integration evidence трансляції projection.
- [x] T061 Налаштувати справжній ArchitectureTests project (test SDK, test framework і правила залежностей) та додати правило, яке не допускає залежність Catalog.Application від Infrastructure/EF. Запустити цей suite в CI-targeted перевірках.
- [x] T062 Усунути або документально прийняти ризик `Microsoft.OpenApi 2.3.0` (`GHSA-v5pm-xwqc-g5wc`) після перевірки сумісної безпечної версії; не оновлювати залежність без окремої суміснісної перевірки Host/OpenAPI.
- [x] T063 Запустити unit, PostgreSQL integration, architecture tests і `dotnet build src/Bootstrapper/Host.Api/Host.Api.csproj --no-restore`; зафіксувати точні результати.

## Checkpoint

Product Application повертає очікувані `Ardalis.Result` також при невалідних
категоріях і конкурентних unique conflicts, не використовує випадкові ключі для
фото, має SQL projection для admin detail і автоматизований контроль меж шарів.

## Виявлені ризики

- Поточна FK-помилка відсутньої категорії може вийти як infrastructure exception.
- `Random.Shared` для `ProductPhotoId` може дати колізію та не є детермінованим для тестів.
- Попередня перевірка унікальності не захищає від паралельного запису.
- Поточний detail handler materialize-ить aggregate замість SQL projection.
- `tests/ArchitectureTests` не є налаштованим test project і не виконує layer rules.
