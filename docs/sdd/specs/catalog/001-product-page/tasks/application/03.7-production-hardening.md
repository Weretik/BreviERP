Усунути ризики для промислового середовища, виявлені під час аудиту реалізації Application
Product. Підфаза не змінює HTTP-контракти: API-наслідки виконуються лише у фазі 04.

- [x] T057 До `CreateProductCommandHandler` і `ReplaceProductCommandHandler` додати перевірку, що всі передані `CategoryIds` існують **до** зміни агрегату або операції запису; відсутня категорія повертає погоджений `Result.Conflict` без `DbUpdateException`.
- [x] T058 Узгодити та реалізувати стратегію локального `ProductPhotoId` без колізій, придатну до тестування, замість `Random.Shared`; додати тести для кількох фото одного Product.
- [x] T059 Перетворити стан гонитви за унікальні `Id`/українську назву/російську назву/slug на `Result.Conflict`: порушення унікального обмеження БД під час створення/оновлення не має вийти назовні як 500. Додати інтеграційні тести конкурентного або еквівалентного сценарію порушення обмеження.

Зберегти повний погоджений контракт деталей і додати інтеграційні докази трансляції проєкції.
- [x] T061 Налаштувати справжній проєкт ArchitectureTests (SDK для тестування, тестовий фреймворк і правила залежностей) та додати правило, яке не допускає залежність Catalog.Application від Infrastructure/EF. Запустити цей набір у цільових перевірках CI.

- [x] T063 Запустити модульні, інтеграційні тести PostgreSQL, архітектурні тести й `dotnet build src/Bootstrapper/Host.Api/Host.Api.csproj --no-restore`; зафіксувати точні результати.

## Контрольна точка

Product Application повертає очікувані `Ardalis.Result` також при невалідних
категоріях і конкурентних конфліктах унікальності, не використовує випадкові ключі для
фото, має SQL-проєкцію адміністративних деталей і автоматизований контроль меж шарів.

## Виявлені ризики

- Поточна помилка зовнішнього ключа для відсутньої категорії може вийти як виняток Infrastructure.
- `Random.Shared` для `ProductPhotoId` може дати колізію та не є детермінованим для тестів.
- Попередня перевірка унікальності не захищає від паралельного запису.
- Поточний обробник деталей матеріалізує агрегат замість SQL-проєкції.
- `tests/ArchitectureTests` не є налаштованим тестовим проєктом і не виконує правила шарів.

## Перевірка

- `dotnet test tests/UnitTests/UnitTests.csproj --no-restore` — пройшли 30/30 тестів.
- `dotnet test tests/IntegrationTests/IntegrationTests.csproj --no-restore` — 7/7 успішно з тимчасовою базою PostgreSQL. Покрито DB unique-constraint → `Result.Conflict` у command pipeline та SQL translation `ProductAdminDetailSpec`.
- `dotnet test tests/ArchitectureTests/ArchitectureTests.csproj --no-restore` — 1/1 успішно; Catalog.Application не має прямих посилань на Infrastructure модулів Catalog/Reference або EF Core.
- `dotnet build src/Bootstrapper/Host.Api/Host.Api.csproj --no-restore` — успішно з одним наявним попередженням `CS8604` у `Identity.Infrastructure/Seeders/RoleSeeder.cs`. `Microsoft.OpenApi 2.7.5` є виправленою версією гілки 2.x для `GHSA-v5pm-xwqc-g5wc`.
