# Підфаза 03.9 — Performance admin Product list query

**Залежить від:** `03.8-catalog-read-model-enrichment.md`
**Пов’язана verification:** `../verification/05.3-admin-list-query-performance-verification.md`

- [x] T083 Переробити list read path: page query не materialize-ить кілька collection navigation; застосувати локальні split queries або bounded batch projections без N+1, зберігши filter/sort/page/total та DTO contract.
- [x] T084 Додати integration tests для відсутності `MultipleCollectionIncludeWarning` і bounded SQL command count; розширити list tests перевіркою `categoryIds`, main photo URL/null і `minimumWholesalePrice`.

## Checkpoint

`GET /api/v1/products` зберігає контракт і уникає cartesian collection materialization/N+1.

## Результати реалізації

- Baseline: ручний Host API log за 2026-08-19 — `MultipleCollectionIncludeWarning`,
  `GetAdminProductsQuery` 7740 ms і HTTP `GET /api/v1/products` 9142 ms.
- Після warm-up без перезапуску Host API той самий порожній list повернув `200 OK` за
  323.7063 ms і 172.2967 ms; slow warning відсутній. Первісний baseline є cold-start,
  а не сталою затримкою empty list.
- `GetAdminProductsSpec` тепер застосовує локальний `AsSplitQuery()` після
  `AsNoTracking()`. Це не змінює filter, sort, page, total або `ProductListItemReadModel`,
  але усуває cartesian collection materialization; кількість split queries стала для
  projection і не залежить від кількості Product у page.
- Новий PostgreSQL integration test `List_projection_uses_split_queries_for_multiple_collections`
  переводить `RelationalEventId.MultipleCollectionIncludeWarning` у exception, а
  `List_projection_command_count_is_independent_of_page_size` підтверджує однакову
  кількість reader-команд для page size 1 та 2; обидва проходять.
- `dotnet test tests/IntegrationTests/IntegrationTests.csproj --no-restore --filter FullyQualifiedName~GetAdminProductsSpecTests` — 5 passed.
- `dotnet test tests/IntegrationTests/IntegrationTests.csproj --no-restore --filter
  FullyQualifiedName~GetAdminProductsSpecTests` — 5 passed.
- End-to-end latency вимірювання не є завданням цієї реалізаційної підфази та не внесене до її
  критеріїв виконання.
