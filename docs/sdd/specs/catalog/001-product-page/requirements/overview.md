# Product page — overview and scope

**Module:** Catalog\
**Status:** implemented and verified\
**Owner:** Catalog\
**Created:** 2026-07-27

## Goal

The catalog manager creates and extends a product with Ukrainian and Russian names, a slug, type, photos, and categories. Product data must be sufficient for a complete admin frontend where the manager can view and configure every product property.

For a `Sewing` product, the manager selects sewing operations, and the system displays labor time, the full fractional number of products per shift, and three calculated prices for each selected fabric.

## Product types and shared data

A product has one type: `Sewing` or `Ppe`. Both types support:

- Ukrainian and Russian names;
- a slug automatically generated by the system from the Ukrainian name;
- photos, usable only after the media file is ready;
- categories;
- a description, information blocks, and characteristics.

## General rules

- Ukrainian and Russian names are required, each up to 200 characters, and each is unique within Catalog. The system generates the slug from the Ukrainian name through a transliteration package; the type is explicit.
- A category or media file cannot be added twice.
- If a product has photos, at least one is primary; after removing the primary photo, the next one by order is selected.
- A `MediaFile` linked to a Product through a photo cannot be deleted until the link is removed from the product. Deletion is rejected without changing Product.
- Admin can create, view, edit, and fully delete Product. Deleting Product removes its own details and links but does not delete `MediaFile`: the file remains in Media and can be reused.
- Editing uses one full `PUT` of Product: the frontend sends all editable shared and type-specific data. When `ProductType` changes, the old data for the other type is deleted.
- Sewing and PPE data are mutually exclusive; the rules for each type are described in their respective requirement documents.

## Decision status and open questions

### Accepted

- Sewing prices are calculated on read for each `Product — Fabric` pair; no snapshot or separate price table is created.
- `piecesPerShift` is passed as a fractional value without rounding.
- Product can have multiple categories; the same `ProductCategoryId` cannot be added twice.
- A Sewing product can have up to two primary fabrics; they are displayed first. For each price tier, the read model returns the minimum and maximum price across all fabrics together with the `FabricId`.
- All Product descriptive content is localized in Ukrainian and Russian: `Description`, `Information`, and `Characteristics`.
- `Description` is sent as sanitized Markdown, `Information` as an array of `heading + plain-text` blocks, and `Characteristics` as an array of tables with `parameter + value` rows; HTML is not sent.
- The current delivery covers only the admin read model. It returns all configurable Product data: shared fields, photos, categories, descriptive content, Sewing/PPE details, fabrics, accessories, operations, Sewing metrics, and calculated prices. The public storefront endpoint is outside the current delivery.
- Temporarily, all Product admin read and write scenarios are available anonymously. An authorization policy must be agreed and enabled separately before production; current anonymous access is not a production decision.
- `Idempotency-Key` is not used in the current admin delivery: the frontend blocks repeat clicks while a request is in progress, and updates use `ProductId`. If a confirmed duplicate-create issue appears, add the key in a separate change.
- Admin does not enter `Slug`, and it is not sent in create/update requests. Application generates it automatically from the Ukrainian name through a transliteration package; the database enforces slug uniqueness within Catalog with a unique index.
- Ukrainian and Russian name uniqueness is guaranteed by Application and unique database indexes. Therefore numeric suffixes are not used for slugs: a slug is a direct transliteration of the Ukrainian name.
- The administrator enters the ID of a new Product. It must be positive and unique in Catalog; repeating the same ID is rejected as a conflict.
- HTTP `type` is required on create, replace, and in every Product response. It is sent as the string `Sewing` or `Ppe`, never as a numeric enum value. Admin can change the type only through a full `PUT`; the frontend sends the full state of the new type's block, replacing the previous block.
- The admin Product list supports one search across Ukrainian and Russian names and ID; `Slug` is not searched. One numeric token searches for an exact ID. Text search is case-insensitive, partial, and token-based: input is split on spaces, and each token must match at least one localized name. Filtering by product type and one category is also available. If the selected category is a parent, filtering includes products in it and all its child categories. Results are paginated: 20 products by default; the frontend can choose 10, 20, or 50 per page.
- Admin can sort the list by ID, name, creation date, or modification date, in ascending or descending order. By default, the list sorts by name from A to Z.
- The admin list sends `mainPhoto` only when a primary photo is selected: the object contains `mediaFileId` and a ready `url`; without a primary photo, the value is `null`. Other photos are not included in the list.
- Each admin list item sends `minimumWholesalePrice`. For Sewing, it is the minimum of all available calculated prices across all selected fabrics and three price tiers; for PPE, it is the calculated wholesale price. If no price can be calculated for the product, the numeric value `0` is sent.
- The admin detail response sends all photos with `mediaFileId` and a ready `url`, as well as all applicable prices: for Sewing, all prices by fabric and tier; for PPE, `basePrice`, retail/wholesale percentages, `retailPrice`, and `wholesalePrice`.
- The Admin Product API uses the `/api/v1` version prefix.
- Price and production-standard history is outside the current delivery. The admin read model always shows current `GarmentPartOperation.Min`, fabric/accessory prices, and `AdditionalReference.Value`; no snapshot/history tables are created.
- Every `AdditionalReference` value with unit `%` is treated as a percentage: formulas use `Value / 100`, not a ready-made multiplier.
- All workshop salary components in Sewing cost—seamstress, bonus, cutter, master, and foreman—are calculated per product. Monthly `srZpShvei` is used only to initially calculate the seamstress's per-unit salary.
- PPE has a required manual `BasePrice`; separate retail and wholesale percentages, sourced from `AdditionalReference` or entered manually, are applied to it.
- `GarmentPartOperation`, `Fabric`, and `GarmentAccessory` cannot be deleted from Reference if at least one Product refers to them. Deletion is rejected without changing Product; link-cleanup events are not used.
