# Product page — checklist: готовність специфікації

Це перевірка якості вимог перед початком реалізації. Вона не замінює і не дублює статус конкретних задач у підфазах `tasks/**/NN.N-*.md`.

## Повнота та межі

- [x] Для Sewing і PPE явно визначено, які дані дозволені, обов’язкові та заборонені.
- [x] Для Description, Information і Characteristics погоджено локалізацію, формат Markdown і allow-list.
- [x] Кожна незавершена тема має один із статусів: «прийнято», «поза scope» або `[NEEDS CLARIFICATION]`; немає прихованих припущень.
- [x] Ціноутворення має окремо погоджену формулу або явно виключене з поточного delivery.
- [x] Погоджено кількість категорій, slug uniqueness, правила медіафайлів і потребу в історії виробничих норм.
- [x] Погоджено межу list/detail: list містить лише головне фото з URL/null і `minimumWholesalePrice`; detail містить усі фото з URL та всі застосовні ціни.

## Узгодженість артефактів

- [x] Кожна вимога з `requirements/` має відповідне рішення в `design/` або явно позначена як відкладена.
- [x] Кожна сутність і зв’язок у `data-model.md` випливає з вимоги; немає speculative таблиць або полів.
- [x] Кожна реалізовувана вимога має хоча б одну конкретну задачу в підфазі `tasks/**/NN.N-*.md`; задачі не додають функціональності поза вимогами.
- [x] Вимоги не описують конкретні controller, EF configuration чи інші деталі реалізації, якщо це не обмеження предметної області.

## Готовність контракту та інтеграцій

- [x] Визначені admin/public API-аудиторії, authorization, idempotency ризики та error contract.
- [x] `docs/sdd/contracts/catalog/product-catalog.openapi.yaml` погоджено до створення HTTP-коду.
- [x] Видалення використаних `GarmentPartOperation`, `Fabric` і `GarmentAccessory` відхиляється; автоматичного очищення посилань і подій немає.

## Рішення gate

Переходити до `tasks/01-domain.md` можна лише якщо всі застосовні пункти позначені `[x]`, або невиконаний пункт офіційно винесений за межі поточного delivery.
