# Product page — checklist: готовність специфікації

Це перевірка якості вимог перед початком реалізації. Вона не замінює і не дублює статус T001–T040 у `tasks/`.

## Повнота та межі

- [ ] Для Sewing і PPE явно визначено, які дані дозволені, обов’язкові та заборонені.
- [ ] Для Description, Information і Characteristics погоджено локалізацію, формат Markdown і allow-list.
- [ ] Кожна незавершена тема має один із статусів: «прийнято», «поза scope» або `[NEEDS CLARIFICATION]`; немає прихованих припущень.
- [ ] Ціноутворення має окремо погоджену формулу або явно виключене з поточного delivery.
- [ ] Погоджено кількість категорій, slug uniqueness, правила медіафайлів і потребу в історії виробничих норм.

## Узгодженість артефактів

- [ ] Кожна вимога з `requirements/` має відповідне рішення в `design/` або явно позначена як відкладена.
- [ ] Кожна сутність і зв’язок у `data-model.md` випливає з вимоги; немає speculative таблиць або полів.
- [ ] Кожна реалізовувана вимога має хоча б одну задачу T001–T040; задачі не додають функціональності поза вимогами.
- [ ] Вимоги не описують конкретні controller, EF configuration чи інші деталі реалізації, якщо це не обмеження предметної області.

## Готовність контракту та інтеграцій

- [ ] Визначені admin/public API-аудиторії, authorization, idempotency ризики та error contract.
- [ ] `contracts/product-catalog.openapi.yaml` погоджено до створення HTTP-коду.
- [ ] Погоджені contract, delivery/retry, idempotency та observability подій видалення Reference data.

## Рішення gate

Переходити до `tasks/01-domain.md` можна лише якщо всі застосовні пункти позначені `[x]`, або невиконаний пункт офіційно винесений за межі поточного delivery.
